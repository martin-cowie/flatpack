# v0.1.0

First release. An in-memory FTP server, built on libunftp 0.23.1, that forwards uploaded files to Kafka on request.

## Not for untrusted networks

This release has no encryption. FTP usernames and passwords cross the network in clear text, and Kafka traffic is unencrypted (`PLAINTEXT` or `SASL_PLAINTEXT` only). Run it only on a network you trust. FTPS (#4) is planned for v0.2.

## Features

- **Authentication delegated to Kafka.** There is no local user store: the FTP username and password are the user's Kafka credentials, checked against the cluster at login. Supports `PLAINTEXT`, `SASL_PLAINTEXT` with `PLAIN`, `SCRAM-SHA-256` or `SCRAM-SHA-512` (#17).
- **Isolated sessions.** Each session has its own in-memory, flat file store, discarded when the FTP sesion ends. Supports `STOR`, `RETR`, `DELE` and `RENAME`; subdirectories are not supported.
- **`SITE SEND`** publishes uploaded files to the session's Kafka topic, with optional message headers.
- **`SITE TOPIC`** reports or sets the session's Kafka topic (#22).
- **`SITE TOPICS`** lists the Kafka topics on the cluster (#22).

## Configuration

Settings live in `config.toml` (copy `config.toml.example`; pass `--config <path>` to use another file).

- `[kafka]`: `brokers`, `default_topic`, `message_timeout_ms`, `auth_timeout_ms`, `security_protocol`, `sasl_mechanism`.
- `[server]`: `port` (default `2121`) and `log_level` (default `info`) (#20).

Passive-mode ports are `50000-65535`.

## Project

- Licensed under Apache-2.0, with publishing metadata (#1).
- Depends on the released libunftp 0.23.1 (#6).
- CI runs the tests and enforces a coverage gate (#11, #14).

## Known limitations

- No TLS on FTP (#4) or between the server and Kafka.
- A Kafka outage is reported as "Authentication failed" (#19).
- `SITE SEND` does not validate content against a topic's schema (#25).
